# `robo-fitting-room` Requirements Tracker

> **Status legend**: DONE (linked to source), PARTIAL (linked + remaining gap noted), NOT STARTED, BACKLOG (deferred)

A pure-Rust multi-backend scene composition and validation engine that ingests URDF structures and 2D CAD floor plans to assemble, validate, and deploy simulation scenes. Backend-agnostic at the manifest level — the same scene YAML drives all supported physics engines (Isaac Sim first, MuJoCo and Gazebo planned).

Target: standalone open-source release.

---

## 1. Definitions

| Term | Meaning |
|------|---------|
| **Dressed URDF** | A composite robot+tool URDF produced by `urdf-robo-dresser`. Tool meshes live under `meshes/tool/`, robot meshes under `meshes/robot/`. |
| **Fixture URDF** | A URDF representing static cell infrastructure (conveyor, fixture, fence) with geometry but only fixed joints. |
| **Scene Manifest** | A YAML file declaring which URDFs to place, at what world-space poses, forming a complete robot cell. Optionally declares a `scene_origin` to centre placements around. |
| **Floor Plan** | A 2D CAD export (DXF→OBJ) containing line geometry (`l` lines and polylines, by `# Layer:` comment, `o` object or `g` group) that represents cell boundaries, fences, and robot footprints. Its vertices are taken Z up as they are (an up axis or rotation for Y-up exports is BL-27); a DXF file isn't read (BL-22). Drawn on the composed stage's ground as flat strip meshes (FR-107). |
| **Station** | A spatial region in the cell assigned to one robot. Contains reachability targets and collision boundaries. |
| **USD Stage** | The OpenUSD scene graph that Isaac Sim operates on. `robo-fitting-room` programmatically populates this as ASCII USDA, packaged into a zip alongside the manifest. |
| **ActionGraph** | An OmniGraph node network embedded in the USD stage that bridges Isaac Sim physics to ROS2 topics and actions. |
| **Trajectory** | A joint-space waypoint sequence defining a robot's planned motion. Used for offline collision checking. |
| **Streaming Client** | Isaac Sim's Kit Remote API for connecting to a running instance and managing stages programmatically. |
| **Deploy** | The act of pushing a composed USD stage to a running Isaac Sim instance via the streaming client. |
| **Force Threshold** | Minimum contact force (N) below which events are filtered as numerical noise (default: 5 N). |
| **Event Debouncing** | Collapsing continuous per-frame contacts into COLLISION_STARTED / COLLISION_ENDED state transitions. |
| **SimBackend** | A Rust trait abstracting backend-specific logic: scene format conversion, deployment protocol, and ROS2 wiring strategy. |
| **Backend** | A physics engine implementation (Isaac Sim, MuJoCo, Gazebo) that the tool can compose scenes for and deploy to. |
| **Home pose** | The joint vector a robot starts in: one value per actuated joint (URDF declaration order, fixed joints excluded), the manifest's `home_pose_deg` (FR-118: degrees, metres on a prismatic joint) or else the KUKA-style "stowed" pose `[0, -90°, +90°, 0, 0, 0]` (FR-117, on the turning joints; a prismatic joint then sits at 0 m). Revolute angles are kept as given (unwrapped: 190° stays 190°), continuous ones are wrapped into (−180°, 180°], prismatic values are metres as given; every value is in the URDF's own convention, along its axis as signed (FR-157). Its one source, `drives::actuated_home_values`, feeds the link bind transforms (FK pre-computed in compose, FR-116), the per-joint drive `targetPosition` and the initial joint state (`PhysicsJointStateAPI`, FR-157), which is what PhysX starts the simulation from. |
| **Link density** | The effective density (kg/m³) of a robot's links: mass per volume of their closed collision geometry (meshes and URDF primitives), not of their material. The manifest's per-robot `link_density_kg_m3`, else `drives::DEFAULT_LINK_DENSITY_KG_M3` (1200). A link whose URDF inertial is a placeholder (its mass over the link's robot geometry less dense than a quarter of the link density, `drives::PLACEHOLDER_DENSITY_FRACTION` = 0.25) takes its mass, centre of mass and inertia from that geometry at this density, and so do tool hulls without a payload. Part of `drives::link_mass_properties`, the one mass source of the emission and the drive tuning (FR-113). |
| **Tool payload** | The rigid mass of the tool a robot carries (manifest `payload`), merged into the link carrying the dressed tool's collision hulls, or the link the manifest's `payload.link` names (FR-159). |

### 2.2 URDF-to-USD Conversion

| ID | Requirement | Priority | Acceptance Criteria | Status |
|----|-------------|----------|---------------------|--------|
| FR-110 | The tool SHALL convert URDF joint/link trees into USD PhysX articulations with correct joint types, limits, and axis definitions: a URDF axis along +X, +Y or +Z is that `physics:axis` token; any other — negative or skewed — keeps its sign and direction by being folded into both joint frames (FR-157). A URDF joint without `<axis>` turns about URDF's default, +X (`urdf-robo-dresser`'s parser). | Must | A 6-DOF revolute arm URDF produces a USD articulation with 6 revolute joints matching the URDF limits (degrees on revolute, metres on prismatic). | [DONE](src/compose.rs#L2837) |
| FR-111 | The tool SHALL convert URDF visual meshes (OBJ) into USD mesh prims with correct relative transforms, and URDF primitives into their UsdGeom prims: a box the unit `Cube` (`size = 1`) scaled to its size by `xformOp:scale`, a cylinder a `Cylinder` along Z (`height`, `radius`), a sphere a `Sphere` (`radius`), each with its `extent` and the default material. An OBJ is bound to its first `usemtl` material only (per-face materials, `GeomSubset`s, are BL-26; compose warns how many OBJs have more than one). Mesh data is inlined per visual (no external references) so Isaac Sim doesn't invoke the asset converter at load time. A mesh's MTL material is bound with its diffuse colour linear: an MTL's `Kd` is sRGB (CAD colours are 8-bit sRGB) and UsdPreviewSurface's `diffuseColor` linear, so each channel is decoded, `c ≤ 0.04045 ? c / 12.92 : ((c + 0.055) / 1.055)^2.4` (`mtl::srgb_to_linear`); written as is, a CAD colour comes out 1.3–1.9× too bright. The default material's 0.45 grey (meshes without a material of their own, the pedestals) is linear already, and a material whose colour isn't known — no `Kd` line, a material its MTL lacks, an MTL that can't be read — gets that same linear grey (`mtl::DEFAULT_DIFFUSE_LINEAR`), not decoded and not a lighter placeholder. | Must | Mesh geometry renders correctly in Isaac Sim viewport; an MTL `Kd 0.5` is bound as `diffuseColor` 0.214041; a material without `Kd`, one missing from its MTL and one whose MTL is missing are bound as 0.45, the default material's. | [DONE](src/compose.rs#L2503) |
| FR-112 | The tool SHALL convert URDF collision meshes into USD collision geometry with `physics:approximation = "convexHull"` and `PhysicsCollisionAPI` + `PhysicsMeshCollisionAPI`, and URDF collision primitives into their UsdGeom prims (FR-111's `Cube`, `Cylinder`, `Sphere`) with `PhysicsCollisionAPI` alone, which PhysX collides with as they are. Only OBJ meshes are read: a mesh that yields no face (an STL or DAE file, BL-25) composes as an empty prim, which compose logs and FR-103 warns about. | Must | PhysX detects collisions using the URDF-defined collision shapes; a box collider is a `def Cube` with `PhysicsCollisionAPI`, its size as `xformOp:scale`, and no convex-hull approximation. | [DONE](src/compose.rs#L2558) |
| FR-113 | The tool SHALL map every link's mass properties (mass, centre of mass, inertia tensor) to `PhysicsMassAPI` — `physics:mass`, `physics:centerOfMass`, `physics:diagonalInertia` and, with every diagonal inertia (UsdPhysics wants both or neither), `physics:principalAxes`, the identity `(1, 0, 0, 0)` when the tensor is diagonal in the link's axes — from one source (`drives::link_mass_properties`) that both the emission and the drive tuning (FR-158) use, with no model-specific table. A link is the sum of two bodies. **(a)** Its robot body, of its robot geometry: its collisions that aren't the tool's (FR-159: `meshes/tool/`, or a named payload link's), or its visuals that aren't when it has no such collision — meshes (origin and scale applied; volume V the sum of the closed meshes' volumes by the divergence theorem, degenerate meshes skipped) and URDF primitives (box, cylinder, sphere: their analytic volume, centroid and inertia). The URDF inertial as authored — its mass, its origin as the centre of mass, its full tensor (products of inertia too) turned into the link's axes by the origin's rpy — when it is usable (mass finite and > 0) and no placeholder: the link has no robot geometry (V = 0), or the inertial's mass over V is at least a quarter of the link density (`drives::PLACEHOLDER_DENSITY_FRACTION` = 0.25). Otherwise the robot geometry at the link density: mass ρ·V, the solid's centroid and inertia. **(b)** Its tool body, of its tool collision hulls: the tool payload when the link carries it (FR-159), else the hulls at the link density. The link density ρ is the robot's manifest `link_density_kg_m3` (finite and > 0, else a validation error), by default 1200 kg/m³ (`drives::DEFAULT_LINK_DENSITY_KG_M3`: heavy six-axis arms' datasheet masses over their links' convex hulls are of the order of 10³ kg/m³, more or less with how closely the hulls wrap; set the manifest's density to match a datasheet). The two bodies are combined by the parallel-axis theorem and diagonalised. A link with neither (no geometry, no usable inertial) gets, so PhysX never falls back to its "negative mass small sphere" path: when it is welded to the URDF root through fixed joints only (nothing moves it), 10 kg with a unit inertia; otherwise — a frame a joint moves, such as a flange, `tool0` or a TCP — 0.1 kg as a solid sphere of 5 cm (1e-4 kg·m²), which doesn't load the chain it hangs on (`drives::FRAME_LINK_MASS_KG`). | Must | Every rigid body carries `PhysicsMassAPI` with positive mass and its principal axes; a 2 kg inertial on a 0.1 m³ box is replaced by the box at 1200 kg/m³ (120 kg, its centroid and tensor), a 60 kg one is kept with its tensor turned by its rpy; the manifest's `link_density_kg_m3` scales the derived masses and the placeholder line (at 2500 kg/m³ the 60 kg is a placeholder too); a tool box without a payload weighs the link density; a box, cylinder or sphere weighs its analytic solid; the root and its welded base without geometry weigh 10 kg, a flange or `tool0` frame 0.1 kg; a density of 0 fails validation. | [DONE](src/drives.rs#L331) |
| FR-114 | The tool SHALL assign deterministic USD prim paths based on the robot ID and link/joint names from the manifest. Names are passed through `sanitize_prim_name` (digit-prefixed names get an underscore, "World" → "world_link" to avoid stage-root shadowing). | Must | Prim paths are predictable and stable across scene reloads. | [DONE](src/compose.rs#L3931) |
| FR-115 | The tool SHALL handle the URDF root link by anchoring it to the USD stage root at the placement pose from the manifest. Implemented as a `PhysicsFixedJoint "world_anchor"` whose `localPos0/localRot0` matches the robot's world placement and whose `body1` rel points at the root link. | Must | Robot base is fixed at the specified world position. | [DONE](src/compose.rs#L1519) |
| FR-116 | The tool SHALL pre-compute forward kinematics in compose so each link's bind pose is its transform (relative to the robot root) at the configured home pose. The bind poses keep every joint's two frames together (omni.physx checks the bodies against the joint frames at load and warns "disjointed body transforms") and show the home pose before Play. They don't set the simulation's start state: when the articulation enters the scene, PhysX overwrites the non-root link poses from the joint positions, which start at FR-157's initial joint state (and at 0 without one). | Must | Each link's `matrix4d xformOp:transform` equals `parent × joint_local × R(axis, home_angle)` (a slide along the axis on a prismatic joint), the axis the URDF's unit axis as signed. | [DONE](src/compose.rs#L3872) |
| FR-117 | When a robot does NOT specify a per-robot home pose (FR-118), the tool SHALL fall back to the KUKA stowed default `[0°, -90°, +90°, 0°, 0°, 0°]`, by actuated joint, on the turning joints (a prismatic joint sits at 0 m; 0 beyond six joints). The same angles are written into the per-link FK bind pose, the per-joint drive `targetPosition` and the initial joint state (FR-157). | Must | Default-everything manifests still produce the stowed pose, as the drive targets and as the start state. | [DONE](src/drives.rs#L35) |
| FR-118 | The manifest SHALL accept an optional `home_pose_deg` field per robot — a list of N values, one per actuated joint of the dressed URDF (fixed joints excluded, declaration order): degrees on a revolute or continuous joint, metres on a prismatic one. The length is validated against the URDF at validate-time; mismatches are rejected with a structured error, and so is a revolute joint's home angle or a prismatic joint's home position (given, or the FR-117 default: 0 m on a prismatic joint) outside its URDF limits (slack 1e-4° and 1e-6 m): the joint would start in violation of its limit. The override drives the FK bind pose, the per-joint `targetPosition` and the initial joint state; revolute angles stay unwrapped (190° stays 190°), continuous ones are wrapped into (−180°, 180°], prismatic values are metres as given. | Must | A manifest with `home_pose_deg: [10, -45, 30, 0, 0, 0]` produces matching `targetPosition` and joint-state values; a slide's `1.25` is its linear target and state, 1.25 m along its axis in the bind pose; a wrong-length list, or a value outside its joint's limits, fails validation. | [DONE](src/scene.rs#L334) |
| FR-119 | The manifest SHALL accept an optional per-robot `pedestal` block (`height_mm`, default 0; `diameter_mm`, default 800) describing an elevated mounting fundament. When `height_mm > 0` the robot is raised by that height (mm→m) and a static collision `Cylinder` of the given diameter is emitted beneath it, spanning the robot's placement height to its raised foot (z = position.z to position.z + height, at the robot's XY: the floor at z = 0, or a platform). Height must be finite and ≥ 0, diameter finite and > 0. The cylinder is bound to the matte default material (`/World/Looks/factoryos_default`), not the renderer's glossy default. Every robot's welded root links (the URDF root and the links fixed to it, e.g. `world_link` and the base) carry `PhysicsFilteredPairsAPI` with `physics:filteredPairs` = its pedestal's cylinder, if it has one, and the ground's collider `/Environment/GroundCollider` (NFR-108): the base hull sits a few mm into what it stands on and neither can move, so their contact would only flood the base's contact reports. | Should | A manifest with `pedestal: { height_mm: 500 }` raises the robot's `xformOp:translate` and `world_anchor` z by 0.5 and produces a `def Scope "pedestals"` with a matte `def Cylinder` (radius 0.4, height 0.5) carrying `PhysicsCollisionAPI`, which the welded root links (only they) filter with the ground: `rel physics:filteredPairs = [</World/pedestals/pedestal_<id>/socket>, </Environment/GroundCollider>]`; without a pedestal they filter `[</Environment/GroundCollider>]`. | [DONE](src/compose.rs#L1922) |

### 2.3 Runtime Tool Swapping

> **Note:** Tool swapping requires a full dresser cycle (`urdf-robo-dresser dress`) to produce a new dressed URDF, followed by a scene recompose and redeploy. There is no in-place USD subtree replacement — the canonical workflow is: re-dress → update manifest → redeploy.

| ID | Requirement | Priority | Acceptance Criteria | Status |
|----|-------------|----------|---------------------|--------|
| FR-120 | The tool SHALL support hot-swapping a robot's tool during simulation runtime by loading a different dressed URDF. | Should | Swap triggers dresser cycle, recompose, and redeploy without manual steps. | BACKLOG |
| FR-121 | The tool SHALL preserve the robot arm's joint state across a tool swap — only the tool subtree is replaced. | Should | After swap, arm joint positions are unchanged; only the tool attachment subtree differs. | BACKLOG |
| FR-122 | The tool SHALL validate the replacement URDF is compatible with the current arm (same flange interface) before executing the swap. | Should | Incompatible swap attempts produce an error without modifying the scene. | BACKLOG |
